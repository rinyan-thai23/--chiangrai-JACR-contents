# 北タイ・チェンライ地域メディア部署

チェンライ県を中心とした北タイの地域密着情報を、日本語のニュース記事としてまとめる部署です。米国アーカンソー州の地域密着ニュースメディア「[OkayNWA](https://okaynwa.com/)」を参考モデルとしています。全国紙が拾わないような「その土地に住む人・関わる人にとって意味のある話題」（防災・行政・生活・観光・文化・国境事情など）を優先し、日本語話者（在住者・移住検討者・渡航者）に届けることを目的とします。

## 起動コマンド

厳密なコマンド文字列ではなく、**意味が近ければ実行してよい**（ファジーマッチ）。以下はあくまで例。

| 送るメッセージの例 | 実施内容 |
|---|---|
| 「部署実行」「いつもの」「北タイニュースお願い」「メディア部署」「今週の記事作って」「土曜配信」など | その週に集まった、基準（「出力フォーマットのルール」「除外している手法」）を満たすネタを**本数の上限・下限を設けず**すべて記事化する。目安は3〜5本程度だが、豊作の週はそれ以上でもよく、基準を満たすネタが1本もなければ0本でよい（後述） |
| 「計画見直し」「方針変更」「プロトタイプ改善」 | [runs/index.md](./runs/index.md) の直近の実行記録を振り返り、本README・取材フローの改善点を検討・反映する |

本数はあらかじめ決め打ちしない。**質の基準を満たすかどうかだけで採否を判断し、本数を埋めるために基準を緩めない。**

## 実行頻度と対象エリア

- **頻度**: 週1回、土曜朝配信（2026-09-10確定。実測ベースの根拠は[2026-09-09の頻度リサーチ](./runs/2026-09-09-frequency-research.md)を参照。それまでの「週2日・1回5本」は実際のネタ密度〈週あたり約2.2件〉に対してオーバーペースだったため見直した）。
- **本数**: 固定しない。ボリュームより先に質を優先し、その週に基準を満たすネタが何本あったかで決まる。**基準を満たす地域密着ネタが1本もない週は、無理に本数を埋めず「今週は掲載基準を満たす地域密着ネタがありませんでした」で0本配信とする。** これは失敗ではなく正常な運用結果として扱い、`runs/`にもその旨をそのまま記録する。
- **優先順位**: ①チェンライ県内 → ②北タイ（チェンマイ・パヤオ・ランパーン等の近隣県、国境をまたぐミャンマー・ラオス側の関連事象含む） → ③タイ全国。**現時点では①を主軸とし、②は関連性が強い場合のみ、③（全国紙が扱うような中央政治・全国マクロ経済等)は原則対象外**とする。
- 全国紙・大手英字メディアの記事をそのまま要約するだけの「タイ全国ニュースの二次紹介」にはしない。あくまで「チェンライ・北タイに住む人の生活にどう関わるか」の視点を主軸に置く。

## 実行内容（1本あたりの制作フロー）

1. **ネタ収集**: 以下の優先順位で情報源にあたる。
   - チェンライ県庁・タイ気象庁・防災局（ปภ.）など公的機関の発表
   - チェンライ現地SNS（Facebookページ・グループ等）・現地ニュースサイト（Chiang Rai Times、Chiangrai Focus、タイ語地方紙等）
   - 全国紙（Bangkok Post、Nation Thailand、Thairath等）の**チェンライ関連記事**（全国面の記事は対象外）
   - **注意**: 本セッションの環境は、開発用ドメイン以外への外部アクセスをほぼ全面的に拒否するネットワークポリシーになっており、ニュースサイト・SNSへの直接アクセス（WebFetch）は原則ブロックされる（詳細は[sources.md](./sources.md)、検証記録は[2026-09-09の実行記録](./runs/2026-09-09-access-survey.md)）。その場合はWeb検索（WebSearch）による複数クエリでの情報収集・クロスチェックを代替手段とする。環境のネットワークポリシーが変更された場合は`sources.md`を再検証・更新すること。
2. **裏取り**: 同じ事実について**最低2系統以上の情報源（できればタイ語ソース＋英語ソース）で数値・地名・日付が一致するか確認**する。一次情報源（公的機関・現地紙）と食い違う場合は一次情報源を優先し、食い違い自体を記事に注記する。
3. **執筆**: 「出力フォーマットのルール」に従って日本語記事を作成する。
4. **保存・記録**: 記事本体を `articles/YYYY-MM-DD-スラッグ.md` として保存し `articles/index.md` に追記。取材メモ・出典・裏取り状況は `runs/YYYY-MM-DD.md` に記録する。
5. **配信用セット生成**: `node scripts/build-news-output.mjs` を実行し、`articles/`配下の記事から次を自動生成する（2026-09-10追加、まとめHTML化・カード型デザインへの変更も同日、詳細は[配信先](#配信先)を参照）。
   - `html/YYYY_MM_DD.html` … その号（配信回）の全記事を1ページにまとめたGitHub Pages公開用HTML。サイト名は「チェンライ・北タイローカル情報」（Powered by チェンライ日本人会）。記事はカード型で並び、「続きを読む ↓」ボタンをタップするとその場でトグル（`<details>`）展開する。ボタンはhover前提にせず、タップ操作（`:active`）と開閉状態（`[open]`）だけで完結するようにしており、スマートフォンでの閲覧を主眼に置いている。マストヘッド直下には、山・川の線画と取材拠点をイメージした装飾SVGアニメーション（CSSのみ、JS不要）を毎回表示する。高齢の読者にも配慮し、配色はライトモード・文字サイズは大きめ、装飾より可読性を優先したシンプルなレイアウトにしている。出典欄は媒体名と確認日のみを表示し、各出典の英語・タイ語見出し引用と、記事末尾の注記（取材手法の免責文）はこのHTML・ブログ版に限り省略する（`articles/`本体と`newsletter/`では従来通り残す）。
   - `blog/YYYY_MM_DD.md` … ブログ投稿専用（2026-09-10改訂）。`html/`とは別物で、カード・トグルは使わない。1行目をタイトル「チェンライ/北タイ 週間ローカルニュース YYYY/MM/DD」とし、直後に各記事への目次を置いた上で、`articles/`配下のmdをそのまま（英語・タイ語見出し引用や注記も含めて）連結しただけのシンプルな1ファイル。
   - `newsletter/YYYY_MM_DD.md` … 号ごとに1ファイル（2026-09-10改訂、記事ごとにファイルを分けない。`articles/index.md`が全履歴を1ファイルで持っているのと同じ考え方）。メール・FB・LINE等の既存ニュースレター登録メンバーに送る、各記事のURL付き紹介文を`---`区切りで連結する（リンク先は`html/YYYY_MM_DD.html`内の該当記事のアンカー）。
   - デフォルトでは`articles/`配下の記事を実行日付ですべてまとめる。特定の記事だけをその号に含めたい場合は `node scripts/build-news-output.mjs --date=YYYY-MM-DD スラッグ1 スラッグ2 ...` のように号の日付とスラッグを明示して実行する。
   - 記事本文（`articles/`）を修正した場合は、配信前に必ずこのスクリプトを再実行して最新化すること。

## 配信先

- **GitHub Pages（号ページ本体）**: `html/`配下のHTMLファイルが実際に配信するページ。その号の記事をすべて1ページにまとめ、記事ごとにトグル展開する構成。URLは `https://rinyan-thai23.github.io/--chiangrai-JACR-contents/NEWS-north-thailand-media/html/YYYY_MM_DD.html` の形式（長さは気にしない）。既存のメール・FB・LINEニュースレターへは、このURL（記事ごとのアンカー付き）を`newsletter/`のテキストと合わせて送る。
- **ニュースレター（メール／FB／LINE）**: `newsletter/YYYY_MM_DD.md` を使う。号ごとに1ファイルで、各記事のタイトル・リード・エリアタグ・上記GitHub Pages号ページへのアンカー付きURLが`---`区切りで並ぶ。配信時は必要な記事のブロックだけを抜き出して使ってもよい。
- **ブログ投稿**: `blog/YYYY_MM_DD.md` を使う。`html/`のカード・トグルUIは使わず、`articles/`のmdをそのまま結合した読み物として掲載する（英語・タイ語見出し引用・注記も省略しない）。
- **GitHub（本流・一次情報としての記事）**: `articles/`配下のMarkdownを一次データとして保持する。記事の完成条件は「GitHub上でそのまま読める状態でarticles/に保存されていること」に加え、上記の配信用3点セットが生成済みであること。
- **WordPress（転載先）**: 別途運営しているWordPressサイトにも同じ記事を転載する。投稿の自動化フローは本リポジトリの外（別システム）に既に構築済みのため、**本部署のタスクとしては上記3点セットを生成するところまでとし、WordPressへの反映・自動投稿の仕組み自体はこのリポジトリでは扱わない**（将来、連携が必要になった場合はその時点で本README・runs/に追記する）。

## 出力フォーマットのルール

- ファイル冒頭に以下のメタ情報を記載する。
  - タイトル（日本語、扇情的な煽り見出しにしない。事実を要約した見出し）
  - 一言リード（絵文字なし。何が起きた／何が変わるのかを1〜2文で）
  - エリアタグ（例: `#チェンライ #メーサイ`）
  - 最終更新日時・取材日
- 本文は「結論→詳細→今後の見通し・生活への影響→出典」の順で書く。
- **読みやすさ（2026-09-10追加）**: 1段落は短く（目安2〜4文）改行し、文の長さに緩急をつけて読むテンポを作る。冒頭や場面転換に、事実に基づく短い一文（すでに本文で書く内容を前に出すだけでよい）を置くのは構わないが、事実を誇張・創作しないこと。あくまで「読み物として最後まで読ませる」ための文章のリズムの話であり、下記の煽情禁止・断定禁止のルールを緩める意味ではない。
- **数値（水位・雨量・件数・日付等）は必ず出典と紐づけ、出典元で確認できない数値は書かない。**
- 記事末尾に出典を必ず列挙する（URL・媒体名・確認日）。出典が英語・タイ語の場合、日本語は要約・翻訳であり、原文の見出し的な表現をそのまま煽情的に転載しない。
- 断定できない情報（未確定情報・噂・SNS上の未検証投稿）は「〜との情報がある（未確認）」と明記し、確定事実と区別する。
- 個人（一般市民）の氏名・顔写真等は、公人・報道価値がすでに広く公知の場合を除き、記事の主題上必要でなければ伏せる。

## 除外している手法（採用しない）

- 出典を確認できない情報を断定表現で記事化すること（**捏造・誤情報の掲載は最重要禁止事項**）。
- 全国紙が扱うような中央政治・全国レベルのマクロニュースの単純紹介（地域密着から外れるため）。
- SNS上の個人投稿を、本人の許諾なく実名・個人特定可能な形で無断転載すること。
- 事故・事件・災害等の被害者を扇情的・見世物的に扱う見出し・表現。
- 単一の未検証ソースのみに基づく記事化（最低限の裏取りを省略すること）。

## 運用ルール

- 本リポジトリの運用ルール（ルートの`CLAUDE.md`）に従い、フィーチャーブランチは作成せず、`main`ブランチに直接コミット・プッシュする。
- 実行結果（取材メモ・裏取り状況・課題）は必ず`runs/`に記録し、成果物である記事本体は`articles/`に保存する。README本体を実行結果で肥大化させない。
- egressアクセス制限や情報源の偏りなど、運用上の制約に気づいた場合は`runs/`の記録に残し、次回以降の改善につなげる（プロトタイプとして走らせながら継続的に改善する方針）。
- 将来的に対象エリアを北タイ全体・タイ全国に広げる場合は、この README の「対象エリア」節を改訂してから着手する。
- **将来の独立運用（部署引っ越し）について**: この`departments/north-thailand-media/`フォルダは、本格運用に移行した際に別リポジトリへフォルダごと移すことを想定している。フォルダ内のリンクはすべて相対パス（`./`・`../`）でフォルダ内に閉じており、リポジトリのルート（`departments/README.md`や他部署）への依存は「運用ルールはルートのCLAUDE.mdに従う」という一文のみ。フォルダを新リポジトリのルート直下（またはそれに準じる場所）にそのまま置けば、移行先の新しいCLAUDE.mdの運用ルールに従う形でそのまま機能する。新しいファイルを追加する際も、この自己完結の原則（フォルダ外への相対パス参照を作らない）を崩さないこと。移行を実施した際は、旧リポジトリの`departments/README.md`の部署一覧からも本部署の行を削除すること。

## 実行記録

司令を受けて実行した結果は `runs/YYYY-MM-DD.md` として日付ごとに保存する。過去の実行履歴・累積の改善点は [runs/index.md](./runs/index.md) を参照。新しい実行時は [runs/_template.md](./runs/_template.md) をコピーして使う。制作した記事の一覧は [articles/index.md](./articles/index.md) を参照。情報源ごとのアクセス可否・代替手段は [sources.md](./sources.md) を参照。
